## 第 2 节 · 数据库方言限制（踩中就直接语法报错）

这个库是 **PG 9.2 内核 + Oracle 兼容模式（DBCOMPATIBILITY=A）**，以下写法**禁止使用**：

| 禁止 | 原因 | 必须改成 |
|---|---|---|
| `GENERATED ALWAYS AS IDENTITY` | 语法错 42601 | 主键用 `SERIAL` |
| `ON CONFLICT (x) DO ...` | 语法错 42601 | `ON DUPLICATE KEY UPDATE` |
| `count(*) FILTER (WHERE ...)` | 语法错 42601 | `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` |
| `LATERAL` | 语法错 42601 | 改成子查询或相关子查询 |
| 双引号包裹标识符 / 驼峰表名 | 会被折成小写导致找不到表 | 全小写下划线 |
| 跨库查询 `库名.表名` | 不支持 | 单库 `hospital`，表都在 `public` 下 |

**字符长度陷阱（必须遵守）**：`VARCHAR(n)` 的 n 是**字节数**，1 个汉字占 3 字节。

| 用途 | 类型 |
|---|---|
| 编号、状态码 | `VARCHAR(20)` |
| 姓名、科室名、职称 | `VARCHAR(60)` |
| 地址、备注、原因 | `VARCHAR(200)` |
| 金额 | `NUMERIC(10,2)` |
| 日期 / 时间 | `DATE` / `TIMESTAMP` |

可用且推荐：`SERIAL`、窗口函数、`WITH ... INSERT`、`string_agg`、`LIMIT/OFFSET`、`DATE - DATE`（得整数天）。

## 第 3 节 · 表结构（8 张，按此实现，不要自行增删字段）

**dept 科室**：`dept_id SERIAL PK`、`dept_name VARCHAR(60) NOT NULL UNIQUE`、`dept_phone VARCHAR(20)`、`location VARCHAR(100)`、`status VARCHAR(20) NOT NULL CHECK IN ('启用','停用') DEFAULT '启用'`

**doctor 医生**：`doctor_id SERIAL PK`、`doctor_name VARCHAR(60) NOT NULL`、`dept_id INT NOT NULL FK→dept`、`title VARCHAR(60) NOT NULL CHECK IN ('主任医师','副主任医师','主治医师','住院医师')`、`reg_fee NUMERIC(8,2) NOT NULL CHECK >0`、`phone VARCHAR(20)`、`status VARCHAR(20) DEFAULT '在职' CHECK IN ('在职','离职')`

**patient 患者**：`patient_id SERIAL PK`、`patient_name VARCHAR(60) NOT NULL`、`gender VARCHAR(10) CHECK IN ('男','女')`、`birth_date DATE`、`id_card VARCHAR(30) UNIQUE`、`phone VARCHAR(20)`、`address VARCHAR(200)`、`create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP`

**schedule 排班**：`schedule_id SERIAL PK`、`doctor_id INT NOT NULL FK→doctor`、`work_date DATE NOT NULL`、`period VARCHAR(20) NOT NULL CHECK IN ('上午','下午')`、`slot_total INT NOT NULL CHECK >0`、`status VARCHAR(20) DEFAULT '正常' CHECK IN ('正常','停诊')`、**`UNIQUE(doctor_id, work_date, period)`**

**slot 号源**：`slot_id SERIAL PK`、`schedule_id INT NOT NULL FK→schedule`、`seq_no INT NOT NULL CHECK >0`、`status VARCHAR(20) DEFAULT '可挂' CHECK IN ('可挂','已挂','停用')`、**`UNIQUE(schedule_id, seq_no)`**、`status` 上建索引

**registration 挂号单**：`reg_id SERIAL PK`、`patient_id INT NOT NULL FK→patient`、`slot_id INT NOT NULL UNIQUE FK→slot`、`reg_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP`、`reg_type VARCHAR(20) CHECK IN ('普通','专家')`、`reg_fee NUMERIC(8,2) NOT NULL`、`status VARCHAR(20) DEFAULT '已挂号' CHECK IN ('已挂号','已就诊','已退号')`、`operator_id INT FK→sys_user`、`refund_time TIMESTAMP`、`refund_reason VARCHAR(200)`

**charge 收费单**：`charge_id SERIAL PK`、`reg_id INT NOT NULL UNIQUE FK→registration`、`amount NUMERIC(8,2) NOT NULL CHECK >=0`、`pay_method VARCHAR(20) CHECK IN ('现金','微信','支付宝','银行卡')`、`pay_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP`、`status VARCHAR(20) DEFAULT '已收费' CHECK IN ('已收费','已退费')`、`operator_id INT FK→sys_user`

**sys_user 用户**：`user_id SERIAL PK`、`username VARCHAR(30) NOT NULL UNIQUE`、`pwd_hash VARCHAR(100) NOT NULL`、`role VARCHAR(20) NOT NULL CHECK IN ('挂号员','医生','管理员')`、`doctor_id INT FK→doctor`（可空）、`status VARCHAR(20) DEFAULT '启用' CHECK IN ('启用','停用')`

外键顺序：dept → doctor → schedule → slot → registration → charge；sys_user 最后建（被 registration.operator_id 引用，可先建表后加约束）。

## 第 6 节 · 业务规则（AI 最容易写错的地方，逐条落实）

1. **剩余号数不存字段**，用 `SELECT COUNT(*) FROM slot WHERE schedule_id=? AND status='可挂'` 实时算。
2. **重复挂号靠数据库拦**：`registration.slot_id` 有 UNIQUE 约束。挂号流程是「开事务 → `UPDATE slot SET status='已挂' WHERE slot_id=? AND status='可挂'` → 判断影响行数，为 0 说明被抢 → `INSERT registration` → 提交」。**禁止先 SELECT 再 INSERT**。
3. **退号是一个事务**：改 `registration.status='已退号'` + `refund_time` + `refund_reason`，改 `slot.status='可挂'`，若有 `charge` 则改 `status='已退费'`。任一失败整体回滚。
4. **只有 `status='已挂号'` 且就诊日期是今天**的挂号单可退，`已就诊` 不可退。
5. **挂号费快照**：挂号时把 `doctor.reg_fee` 复制进 `registration.reg_fee`，之后医生调价不影响历史单据。
6. **停诊**：`schedule.status='停诊'` 时，该排班下 `status='可挂'` 的号源全部改 `停用`；已挂号的单据不自动退，只在查询里标红提示。
7. **密码存 SHA-256**，不存明文；初始账号：`admin/123456`（管理员）、`guahao/123456`（挂号员）、`doctor1/123456`（医生）。
8. **权限**：按 `role` 控制菜单可见性与操作按钮；医生只能看自己的号（`sys_user.doctor_id`）。

# 协作接入说明（发给组员）

> 仓库：https://github.com/Biana0215/Java-Database-Design （Private）
> 前提：已把你加为 collaborator，并接受了邮件邀请。

## 一、克隆

用 **HTTPS** 地址（不要用 SSH，见文末说明）：

```bash
git clone https://github.com/Biana0215/Java-Database-Design.git
```

首次推送会弹出浏览器登录 GitHub，登录你自己的账号即可，之后 Git 会记住凭据。

## 二、配置数据库（每人在自己电脑上做一次）

1. 进入 `tools/环境验证/`，把 `db-opengauss.properties.template` 复制一份，
   改名为 `db-opengauss.properties`（这个文件不会被提交）。
2. 把 `password=` 后面填上群里发的密码。
3. `url` 里的地址按群公告填（宿主机的局域网 IP 或 VM 的 IP，以当时公告为准）。

## 三、验证环境

用 IDEA 打开工程，SDK 选 **JDK 26**，然后把 `lib/opengauss-jdbc-5.1.0-og.jar` 加到 Libraries，
运行 `tools/环境验证/DbCheck.java`，参数填 `db-opengauss.properties`。

看到 7 个 `[OK]` 就算通了：

1. 驱动加载 2. 连接 3. 查询 4. 建表 5. 事务回滚 6. 提交+中文 7. 主键唯一约束

## 四、日常协作规矩

- 分支：`main` 只放能跑的版本；自己开 `feat/你的模块` 分支，每天下班前合并。
- 提交信息：`[A] 完成排班生成 F05`，前缀是你的代号。
- 表结构只有 A 能改，改完更新 `sql/01_schema.sql` 并在群里说一声。
- `sql/02_data.sql` 不能单独重跑，要重置数据就按 `01 → 02` 顺序执行。
- 不要手删 `public` 下的表，不要用 `DROP`。

## 五、为什么不用 SSH（重要）

github.com 的 **22 端口在当前网络被封**（连接被拒）。用 SSH 地址会直接 clone 失败：

```
ssh: connect to host github.com port 22: Connection refused
```

两个选择：

- **推荐：用 HTTPS 地址**，配合浏览器登录，零配置。
- 一定要用 SSH 的话，在自己电脑的 `C:\Users\你的用户名\.ssh\config` 里加：

```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
```

保存后 `ssh -T git@github.com`，看到 `Hi 你的用户名!` 就通了。

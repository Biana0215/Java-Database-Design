# 医院挂号系统 · 需求一页纸

> 软件系统综合设计课程设计 | 4 人小组 | Java + openGauss
> 版本 v1.0（2026-11-25），提交老师做可行性确认用

## 一、一句话定位

面向医院门诊的**挂号—就诊—收费**闭环管理：管理员维护科室医生与排班，挂号员为患者建号收费，医生查看并确认就诊。

## 二、角色（4 个）

| 角色 | 能做什么 |
|---|---|
| 挂号员 | 患者建档、查号源、挂号、退号、收费、日结 |
| 医生 | 查看本人当日挂号列表、标记已就诊 |
| 管理员 | 科室/医生/排班/号源维护、用户管理、统计报表 |
| 患者 | 不作为系统用户，由挂号员代为操作（不做患者端自助） |

## 三、范围

**做：** 科室与医生资料、排班与号源、挂号与退号、挂号费收取、就诊状态、四类统计报表、登录与角色权限。

**不做（明确排除，防止范围膨胀）：** 在线支付、电子病历与处方、药品与库存、检查检验、医保结算、叫号大屏、患者自助端与微信公众号。

## 五、三条验收场景（做完先跑这三条）

1. **正常挂号**：选内科 → 张医生 → 明天上午 → 剩余 15 号 → 选 3 号 → 生成挂号单 → 收费 → 号源变“已挂”，剩余变 14。
2. **退号**：对上面那张单退号 → 状态变“已退号”，3 号号源回到“可挂”，剩余变 15，退号时间与原因落库。
3. **停诊处理**：把该排班改成停诊 → 未挂的号源变“停用”，已挂号的单在查询里能筛出来提示退号。

## 六、非功能约束

- 单机部署，不依赖外网；数据量按“科室 10 / 医生 40 / 患者 300 / 挂号单 1000”造。
- 界面用 Swing，控制台也可接受，但演示需能直观看到列表与操作结果。
- 数据库：openGauss `hospital` 库（`ENCODING=UTF8`，`DBCOMPATIBILITY=A`），字符列长度按字节计。
- 开发周期 2 周，4 人并行，每日合并一次。

# 医院挂号系统 · 表清单与关系

> 8 张表，全部建在 `hospital` 库 `public` 模式下。
> 字符长度按字节计：1 汉字 = 3 字节，中文列按 3 倍预留（详见 README）。

## 一、表清单

### 1. `dept` 科室

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| dept_id | SERIAL | PK | 科室编号 |
| dept_name | VARCHAR(60) | NOT NULL, UNIQUE | 科室名（20 汉字） |
| dept_phone | VARCHAR(20) | | 联系电话 |
| location | VARCHAR(100) | | 位置（如“门诊楼 2 层”） |
| status | VARCHAR(20) | NOT NULL, CHECK IN ('启用','停用'), DEFAULT '启用' | 停用后不再生成新排班 |

### 2. `doctor` 医生

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| doctor_id | SERIAL | PK | 医生编号 |
| doctor_name | VARCHAR(60) | NOT NULL | 姓名 |
| dept_id | INT | NOT NULL, FK → dept | 所属科室 |
| title | VARCHAR(60) | NOT NULL, CHECK IN ('主任医师','副主任医师','主治医师','住院医师') | 职称 |
| reg_fee | NUMERIC(8,2) | NOT NULL, CHECK (reg_fee > 0) | 挂号费，按职称定价 |
| phone | VARCHAR(20) | | 联系电话 |
| status | VARCHAR(20) | NOT NULL, CHECK IN ('在职','离职'), DEFAULT '在职' | |

### 3. `patient` 患者

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| patient_id | SERIAL | PK | 患者编号 |
| patient_name | VARCHAR(60) | NOT NULL | 姓名 |
| gender | VARCHAR(10) | CHECK IN ('男','女') | |
| birth_date | DATE | | 出生日期，年龄由日期算，不单独存字段 |
| id_card | VARCHAR(30) | UNIQUE | 证件号，建档查重用 |
| phone | VARCHAR(20) | | |
| address | VARCHAR(200) | | |
| create_time | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 建档时间 |

### 4. `schedule` 排班

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| schedule_id | SERIAL | PK | 排班编号 |
| doctor_id | INT | NOT NULL, FK → doctor | |
| work_date | DATE | NOT NULL | 出诊日期 |
| period | VARCHAR(20) | NOT NULL, CHECK IN ('上午','下午') | 半天为一个排班单位 |
| slot_total | INT | NOT NULL, CHECK (slot_total > 0) | 计划放号数 |
| status | VARCHAR(20) | NOT NULL, CHECK IN ('正常','停诊'), DEFAULT '正常' | |

**唯一约束：`UNIQUE (doctor_id, work_date, period)`** —— 同一医生同一天同一半天只能有一条排班，从数据库层杜绝重复放号。

### 5. `slot` 号源

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| slot_id | SERIAL | PK | 号源编号（实际挂的是它） |
| schedule_id | INT | NOT NULL, FK → schedule | 所属排班 |
| seq_no | INT | NOT NULL, CHECK (seq_no > 0) | 序号，如 1、2、3… |
| status | VARCHAR(20) | NOT NULL, CHECK IN ('可挂','已挂','停用'), DEFAULT '可挂' | 三态 |

**唯一约束：`UNIQUE (schedule_id, seq_no)`**；`status` 建普通索引（查剩余号用）。

### 6. `registration` 挂号单

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| reg_id | SERIAL | PK | 挂号单号 |
| patient_id | INT | NOT NULL, FK → patient | 谁挂的 |
| slot_id | INT | NOT NULL, **UNIQUE**, FK → slot | 挂的哪个号 |
| reg_time | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 挂号时间 |
| reg_type | VARCHAR(20) | CHECK IN ('普通','专家') | 由医生职称推导 |
| reg_fee | NUMERIC(8,2) | NOT NULL | **挂号费快照**，见下方说明 |
| status | VARCHAR(20) | NOT NULL, CHECK IN ('已挂号','已就诊','已退号'), DEFAULT '已挂号' | |
| operator_id | INT | FK → sys_user | 挂号员 |
| refund_time | TIMESTAMP | | 退号时间 |
| refund_reason | VARCHAR(200) | | 退号原因 |

**`slot_id` 上的 UNIQUE 是并发防线**：一个号源最多对应一张挂号单，重复挂号由数据库直接拦住（`SQLState=23505`），代码不需要“先查后插”。

| status | VARCHAR(20) | CHECK IN ('已收费','已退费'), DEFAULT '已收费' | |
| operator_id | INT | FK → sys_user | 收费员 |

### 8. `sys_user` 系统用户

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| user_id | SERIAL | PK | |

## 二、关系清单（画 ER 图用）

| 关系 | 类型 | 落地方式 |
|---|---|---|
| 科室 — 医生 | 1 : n | `doctor.dept_id` |
| 医生 — 排班 | 1 : n | `schedule.doctor_id` |
| 排班 — 号源 | 1 : n | `slot.schedule_id` |
| 患者 — 号源 | **m : n** | 由 `registration` 落地（患者挂到某个号源），`slot_id` UNIQUE 使其实际为 1:1 |
| 挂号单 — 收费单 | 1 : 1 | `charge.reg_id` UNIQUE |
| 用户 — 挂号单 | 1 : n | `registration.operator_id` |
| 用户 — 医生 | n : 1（可空） | `sys_user.doctor_id` |

> 画 ER 时注意：`registration` 是“患者 × 号源”这个 m:n 联系的**联系实体**，联系属性是挂号时间、挂号费、状态。这一条在报告里要点明，是 E-R 转换的评分点。

## 三、三个必须在报告里讲清的设计点

### 1. 号源为什么单独一张表

如果把“剩余号数”放在 `schedule` 里做计数器，退号、并发、溯源都无从下手。拆成 `slot` 后：每个号是一条实体记录，挂号 = 占用一条 `slot`，退号 = 释放它。**剩余号数用 `SELECT COUNT(*)` 算出来，不存冗余计数**——这是避免更新异常的直接理由。

### 2. `registration.reg_fee` 是有意冗余，不是范式错误

医生的挂号费会调整，但历史单据必须保留**当时的**价格。所以从 `doctor.reg_fee` 复制一份到挂号单，属于“业务快照”，是反规范化的一种合理用法。报告里要主动说明：若不快照，一旦调价，历史收入统计会全部错乱。

### 3. 退号必须是事务

退号要同时做三件事：`registration.status` 改“已退号”、`slot.status` 改“可挂”、`charge.status` 改“已退费”。三条语句必须在一个事务里，任一失败整体回滚。这是报告“事务与并发控制”一节的真实素材。

## 四、范式自查（写报告时逐表过一遍）

- 所有表主码均为单属性 `SERIAL`，不存在部分函数依赖。
- 检查有无传递依赖：`schedule` 不存医生姓名，`slot` 不存日期与医生，`registration` 不存科室名 —— 均通过外码关联，满足 3NF。
- 唯一需要论证的是 `registration.reg_fee`（见上）。

## 五、待定项

- 是否记录“加号”（超额放号）：暂不做，如需可作为 P2 扩展，`slot.seq_no` 允许超过 `slot_total` 即可。
- 是否记录爽约（挂号未就诊）：暂用 `status='已挂号'` 超过当日 24 点视为爽约，由统计查询推导，不单独存字段。
